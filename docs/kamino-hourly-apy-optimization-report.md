The script asks for March history first. If a reserve has no March history, it falls back to the earliest available history from `2025-01-01`.

## Cost Model

The optimizer includes two execution costs:

1. Jupiter quote loss for cross-mint reserve changes.
2. One Solana base transaction fee for each reserve or pool change.

Withdrawing from one reserve and depositing into another reserve can be bundled into one transaction, so the pool-change fee is modeled as `5,000` lamports per reserve change. Using `SOL = $84.82`, that equals `$0.0004241` per change.

Same-mint reserve moves do not pay Jupiter quote loss. They still pay the `5,000` lamport pool-change fee.

## Script Updates

`scripts/analyze-kamino-hourly-reserves.mjs` now stores Kamino history and Jupiter quotes locally:

- `data/kamino-hourly-reserve-history-cache.json`
- `data/kamino-hourly-jupiter-quote-cache.json`
- `data/kamino-hourly-reserve-analysis.json`

By default, the script reuses a complete cache when the freshest cache is less than one day old. Use `--refresh` to force a network refresh, or `--cache-only` / `--no-fetch` to require cached data.

The script also writes progress logs while parsing markets, reserve histories, and Jupiter quotes. Logs include the current item count, percentage complete, elapsed time, and estimated time remaining, which makes long runs visible instead of appearing stuck after a market with only a few reserves.

## Interpretation

For this March-to-May sample, the practical recommendation is hourly evaluation with fee-aware execution. Rebalancing every hour blindly is not the point; checking every hour lets the optimizer catch short-lived APY spikes, while the fee model prevents changes that do not survive transaction and swap costs.

The result is profitable in this backtest, but it depends heavily on historical APY spikes under the `50%` cap. Treat it as a routing-policy benchmark rather than a forward return guarantee.

## Caveats

- Jupiter quotes were sampled during the analysis run, so they are execution-cost estimates rather than historical quotes.
- Public quote availability can change, so cached Jupiter costs should be refreshed before production use.
- Priority fees, failed transactions, retry costs, rent effects, and account creation are not included.
- The analysis assumes one transaction can withdraw from the old reserve and deposit into the new reserve.
- The raw Kamino cache is intentionally ignored by git because it is large local analysis data.
